# 成长数学

## 等级曲线

**指数曲线**：升到下一级需要 `xp(L) = base × g^(L−1)`。

| g | 30 级是 1 级的 | 81 级是 1 级的 | 特点 |
|---|---|---|---|
| 1.10 | 16 倍 | 2048 倍 | 数字涨得慢 |
| 1.18 | 121 倍 | 56 万倍 | 修仙案例在用：大数字爽感强（5 万 → 282 亿） |
| 1.25 | 647 倍 | 5700 万倍 | 后期数字会非常夸张 |

关键点：**如果奖励按当前级百分比给，g 只影响数字有多大，不影响升级快慢。** 升级速度完全由「每分钟拿到当前级的百分之几」决定。这就是为什么推荐用百分比给奖励：曲线负责爽感，比例负责节奏，两者分开调。

### 升级时间怎么算

每分钟得到当前级的 r（例如挂机每秒 0.2% → 每分钟 12%），升一级的时间约为 `1 / r` 分钟（这里约 8.3 分钟）。

多个来源时，把每分钟的比例相加：
```
r = 挂机 0.12 + 击杀(每分钟 2 只 × 4%) 0.08 + 事件(平均) 0.03 ≈ 0.23  →  约 4.3 分钟一级
```
再乘上各种加成（外观、宗门、丹药）。

### 让升级变慢的正确方法
- 降低比例（例如击杀 15% → 4%）：直接、可预测。
- 在大境界台阶处加「突破」：成功率和道具消耗自然拉长时间，还制造紧张感。
- **不要靠「后期曲线突然变陡」来拖时间**：玩家会感觉突然被卡住，而且原因看不见。

## 属性曲线与对手

- 攻击 `atk(L) = base × h^(L−1)`，h 比 g 小（修仙案例：1.12 对 1.18），这样数字增长跟得上，又不会每级都翻倍。
- 敌人的血量最好**按参与者的实际输出来定**，而不是按等级表定：
  - 普通怪：命中次数在 6–11 次之间（血量 = 打它的人的平均伤害 × 随机次数），保证每只怪都要打几下、又不会打太久。
  - 集体 BOSS：血量 = 在场所有人每秒输出之和 × 1.3（暴击和大招的平均）× 目标总时长（秒），人数少于下限按下限算。这样任何人数的房间都是「约 1 小时打死一只」。
- 这样新人和老玩家在同一场里都有事做，难度不会随着玩家变强而失效。

## 加成怎么叠

- 同类加成相加，不同类相乘：`最终 = 基础 × (1 + 装备% + 外观% + 宠物%) × (1 + 宗门%) × 限时倍数`。相加的那一组不容易失控，相乘的倍数要少、要可控。
- 所有来源走同一个函数（例如 `extra(stat)`），加新系统时不会漏，也方便打印「这个玩家的加成从哪来」。
- 给每种加成一个上限（例如全场光环最多 +9%），防止多个人叠在一起时失控。

## 软上限与平衡

| 问题 | 方法 |
|---|---|
| 某种加成堆得太高 | 设上限，或者收益递减（第 n 颗丹药效果打折） |
| 老玩家碾压新人 | 奖励按百分比；排行分段；和实力无关的奖 |
| 后期没有成长感 | 加横向收集（外观、宠物、图鉴），每一件都给一点属性 |
| 某个最优解让其它选择没意义 | 不同选项给不同类型的加成（攻 / 速 / 经验 / 挂机），而不是同一种的大小差别 |
