# 主题层与换皮

目标：同一套玩法和数值，换一份主题文件就是另一个游戏（修仙版 → 上班版 → 武侠版…）。规则代码里不出现任何给观众看的字。

## 主题文件结构

`config/theme_<id>.json`，四块（骨架见 `assets/theme_template.json`）：

| 块 | 放什么 | 例子 |
|---|---|---|
| `terms` | 通用词，被其它字符串大量引用 | 灵气、灵石、妖兽、宗门、法器、标题 |
| `names` | id → 名字的表。数组按下标，字典按 id | 境界、事件名、事件栏文案、道具、外观、宠物、称号、BOSS、阵名、分页名、榜名、地图名 |
| `commands` | 动作 → 弹幕关键词列表（第一个用于提示文案） | `"use": ["服用", "吃"]` |
| `text` | 所有提示和画面文案，`%` 格式化 | `"sign.done": "{cmd.sign}：{stones}+%d、%s×1"` |

另有 `"id"`、`"art"`（美术目录名）、可选 `"extends"`。

### 占位
- `{qi}` → `terms.qi`
- `{item.herb}` → `names.item.herb`；数组表用下标 `{realm.4}`
- `{cmd.explore}` → `commands.explore[0]`

加载时一次填好（循环 3 遍以支持嵌套：names 引用 terms、text 引用 names）。这样把「灵石」改成「工资」，所有消息跟着变；换皮主题只需覆盖十几项就能跑。

### 继承
`"extends": "xianxia"`：字典逐项深度合并，字符串和列表整个替换。新主题只写和母版不同的部分。

## 加载器 API

模板见 `assets/words.gd`：

```gdscript
Words.use("office")                       # 切主题（启动时、测试里）
Words.text("sign.done", [20, "聚气丹"])    # 模板 % 参数；不给参数时不格式化（保留字面 %）
Words.name("item", "herb")                # 灵草
Words.names("realm")                      # 整张表
Words.id_of("look", "青竹客") / index_of("pet", "灵龙")   # 按名字反查（弹幕里写名字时用）
Words.key("explore") / keys("use")        # 弹幕关键词
Words.term("qi")
Words.art_dir()
```

注意：带 `%%` 的模板必须带参数调用，不带参数的模板里直接写 `%`。

## 代码里怎么改

| 原来 | 改成 |
|---|---|
| `const PILLS := {"pill_qi": {"name": "聚气丹", "weight": 33}}` | 去掉 `name`，`Items.name_of(id)` 内部调 `Words.name("item", id)` |
| `const REALMS := ["炼气", …]` | `const REALM_COUNT := 9` + `Words.name("realm", i)` |
| `return _fail("今日已签到")` | `return _fail(Words.text("sign.already"))` |
| `if line == "击退"` | `if Words.keys("auto_attack").has(line)` |
| `const TABS := ["道具", "材料"]` 然后 `match` 中文 | 用英文 id：`["items", "materials"]`，显示时 `Words.name("bag_tab", id)` |
| `"%s 入座 %d 号位" % [...]` | `Words.text("roster.joined", [...])` |
| 字符串处理拼出的文案（如 `get_slice("，", 0).replace("兑换需", "")`） | 直接写一个返回结构化结果的函数，不要从中文文案里截字 |

### 弹幕解析
按动作 id 遍历关键词：精确匹配的动作一组、前缀 + 参数的动作一组、前缀 + 数字的一组。保持原来的判断顺序，避免关键词互相抢。动作 id 和参数格式永远不变，所以存档、测试、模拟观众都不受主题影响。

### 美术
`Look.art(name)`：先查 `assets/themes/<art>/<name>.png`，再查 `assets/generated/`，再用占位图。预载也要两个目录都扫。

## 用测试守住

1. **key 覆盖测试**：扫描 `scripts/` 下所有源码，找出 `"前缀.名字"` 形式的字面量（前缀是主题 text 里出现过的前缀）以及 `Words.key/name/names/term("…")` 的参数，逐个确认在主题里存在。写错一个字马上报错。仓库外也可以直接跑 `scripts/check_theme.py`。
2. **占位测试**：每个主题加载后，所有字符串里都不能再有 `{`。
3. **换主题等价测试**：同一个种子、同一串动作（用 `Words.key(verb)` 发指令），分别在两个主题下跑 15 分钟：存档快照完全相同，回复文字不同；旧关键词在新主题里不认，没覆盖的关键词继承下来。

## 抽离已有项目时（大重构）

1. 先录**文案快照**（见 verification.md），固定种子跑两轮完整事件，几千行回复和事件。
2. 按模块挪：数据表名字 → 弹幕关键词 → 规则消息 → 画面文案 → 美术路径。每挪一块跑一次测试和快照 diff。
3. 模拟观众里的随机抽签保持数组长度和顺序不变，否则所有随机结果错开，截图和快照都没法比。
4. 改完逐字 diff 快照，再截图对比文字和排版。

## 换皮检查清单

1. **对照表**：把母版每个概念映射到新主题，写进 `docs/DESIGN.md`。先定 `terms`（资源、货币、敌人、组织），大部分文案都引用它们。示例（修仙 → 上班）：

   | 修仙版 | 上班版 |
   |---|---|
   | 宗门 / 30 席位 | 公司 / 30 个工位 |
   | 灵气 / 境界 | 绩效 / 职级（实习生 → 专员 → 主管 → 总监 …） |
   | 灵石 | 工资 |
   | 妖兽入侵 · 击退 | 需求来袭 · 开工 |
   | 世界BOSS | 季度大项目 |
   | 五行幻阵 | 部门大逃杀 |
   | 炼丹房 / 炼器坊 / 法器阁 | 茶水间 / 设备科 / 采购部 |
   | 天雷劫 · 护体 | 老板查岗 · 掩护 |
   | 签到 / 摸索 / 突破 | 打卡 / 摸鱼 / 升职 |
   | 皮肤 / 幻剑 / 仙翼 / 筑仙台 | 工装 / 键盘 / 耳机 / 工位装修 |

2. 建 `config/theme_<id>.json`，`"extends"` 母版，先覆盖 terms、境界、事件名、弹幕关键词，就能跑。
3. 试玩（`--theme=<id> --simulate`），在画面上找还带着母版味道的文字，逐项补进主题文件。
4. 补全名字表：道具、外观、宠物、称号、BOSS、怪、阵名、事件栏文案、剧情和规则说明。
5. 美术：先写这个主题的风格卡（`references/art-pipeline.md`），再照美术清单（如 `tools/art_manifest.json`）生成，放进 `assets/themes/<id>/`，缺的自动用母版的，可以分批出。同一画面里不要混两套风格卡的图。
6. 跑验证：测试（含 key 覆盖和占位）、截图。
7. **玩法不跟着主题改。** 数值不同只改 `game.json`（或主题专属的数值覆盖文件）；要加新规则就加在规则层、所有主题共用，不在规则里判断当前主题。

## 没必要进主题的
- 数字格式（`w`、`亿`）、中文标点：换语言时再说。
- 主播控制台、演示剧本、存档提示：本地工具。演示剧本按主题另写。
- 平台礼物名不能改，礼物效果描述按主题写。
