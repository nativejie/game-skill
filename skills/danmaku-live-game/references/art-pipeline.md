# 美术：风格卡与出图流程

直播画面要在手机上一眼好看、好懂。美术和功能同一轮做完：新功能需要的图当轮生成、接入、截图验收，不先用程序画的占位、以后再补（补的那一轮往往没人记得）。

## 风格卡：每个项目第一天写好

风格不写下来，每张图的提示词各写各的，几十张以后描边粗细、配色、比例都对不上；换一个生图工具（`gpt-image-2.5` 或自己的生图接口）或换一个 Agent，风格就漂了。所以每个项目只有**一处**风格定义，所有提示词都从那里拼。

风格卡放在美术清单的顶层（例如 `tools/art_manifest.json` 的 `style` 和 `sprite_rules`），策划案的画面一节写一段人能读的说明并指向它。字段：

| 字段 | 写什么 | 为什么 |
|---|---|---|
| `style` | 一句话风格前缀：画风、配色、描边、比例、质量词，结尾固定「无文字，无字母，无数字，无logo，无水印，无边框」 | 拼在每条提示词前面；图里不能有字，字一律走主题文件 |
| `sprite_rules` | 抠图素材的构图：主体居中、四周留白、纯色平涂底色（`{key_name}`/`{key_hex}`）、主体不含底色 | 抠图稳定 |
| 视角 | 正前方略俯视 / 正面平视 / 正上方俯视，按素材类别各定一种 | 同一画面里视角混用最显眼 |
| 角色设定 | 主要角色的固定外观（发型、服装、配色、体型） | 同一角色出多张姿势时保持一致；改姿势时把这段原样带上，最好附参考图 |
| 尺寸档 | 每类素材在 1080×1920 画面上画多大、抠图后存多高 | 见下面「尺寸档」 |
| 禁区 | 不画什么：真实品牌、真实公司 logo、伪文字、与底色相近的颜色 | |

拼提示词的顺序：**用途和素材类型 → `style` → 具体内容（名字和主题文件里的叫法一致）→ `sprite_rules`**。不管用 `gpt-image-2.5` 还是自己的生图接口，都从 `style` 拼提示词，并把实际提示词、原图和成品的 SHA-256 记进一个 json（例如 `tools/gen_<批次>.json`），以后能追溯、能重画。

换皮时（同一玩法换主题）新写一张风格卡，规则和布局不动；美术目录按 `assets/themes/<主题>/` 分开，找不到再回落通用目录。

## 出图流程

1. **登记**：在清单里加一条 `name / size / key / height / prompt`。没登记的图不进游戏。
2. **生成**：调 `gpt-image-2.5` 或自己的生图接口，统一走项目里的一个生图脚本，密钥只从环境变量读。失败如实报告（记下次数和错误），不悄悄换工具或用占位顶上。
3. **抠图 + 缩放**：统一走一个脚本（例如 `tools/key_assets.gd`）：抠底色、去溢色、裁透明边、缩到清单的 `height`。透明原图标 `preserve_alpha` 跳过抠色，但**照样缩放**。原图只留在 `art-raw/`，不进游戏目录。
4. **检查**：`python3 <skill>/scripts/check_art.py <美术目录> <清单>`，查没登记的图、没缩放的图、超大的图。
5. **预览**：一张拼图看所有状态（例如 `desk_preview` 把工位各状态拼一张），比跑整轮截图快得多。
6. **截图验收**：按手机视角看（见下）。

## 尺寸档（1080×1920 竖屏）

| 类别 | 画面上 | 存多高 |
|---|---|---|
| 背景 | 整屏 | 1080×1920 裁好 |
| 横幅 / 面板框 | 宽 500–1060 | 100–300 |
| 工位场景、角色 | 150–300 | 200–300 |
| 商品、装修、徽章 | 46–100 | 128–256 |
| 小图标（锁、鱼、火苗） | 24–40 | 64–128 |

存的高度取画面尺寸的 2–4 倍就够清楚。**原图不要直接进游戏**：1254×1254、约 1 MB 的锁图标画成 28px、货架上一次 7 个，同一轮截图运行出现 50–120 ms 的卡顿，它是头号嫌疑。小显示、大贴图既浪费显存，首次上传也慢。启动时预载所有贴图，避免第一次显示时读盘。

## 手机视角验收

1080×1920 的画面在手机上缩小约 2.8 倍。看截图时把它缩到约 386px 宽再看：

- 关键社交信息（谁甩的锅、谁送的礼、排名）在 1080 宽度下不小于 20px；窄格子里的辅助说明放宽到 18px。用自动缩字号塞进去不算通过。
- 状态先用图表现，再决定留哪几个字。
- 表示「更好 / 更贵 / 更稀有」的东西要更大、更亮。加锁、加徽章不能把主体缩小：锁住的升降桌比 30 块的盆栽还小，意思就反了。锁和条件放在主体下沿的小横幅里。
- 小图标贴着容器边缘时检查有没有被截掉。
- 空位、换人后不残留上一个人的状态。

## 美术相关的坑

| 坑 | 发生了什么 | 怎么避免 |
|---|---|---|
| 数据卡片当席位 | 30 个工位全是数字和小头像，用户说太弱 | 席位画成场景，状态用道具和效果，只留几行字 |
| 原图直接进游戏 | 1254px 的锁画成 28px；同一轮 P99 从 17.5 涨到 23.3 ms、7 帧超 33 ms，锁是头号嫌疑 | 所有图走登记 → 抠图缩放 → `check_art.py` |
| 加锁把商品缩小 | 为腾位置把有门槛的商品从 72px 缩到 46px，最贵的反而最小 | 主体尺寸不变，锁和条件压在下沿 |
| 自动缩字号 | 「背锅！XX 甩的」被缩到约 12px，还标成通过 | 关键字 ≥ 20px，缩到 386px 宽目视 |
| 小图标被截 | 工位左下角的小鱼只剩一个三角 | 检查贴边的图标，放不下就去掉 |
| 抠图底色撞色 | 深紫横幅框按品红抠图后变成半透明 | 底色离主体颜色远；框图下先画不透明底 |
| 背景自带布局 | 生成的地面画了走廊，和代码里的位置对不上 | 背景只要均匀地面 / 墙，有布局意义的线在代码里画 |
| 提示词和主题名不一致 | 装修叫「升降桌」「双屏显示器」，提示词写成实木大桌、曲面屏 | 写提示词时对照主题文件里的名字 |
| 图里有字 | 生成图带伪文字，换皮时无法改 | `style` 结尾固定「无文字…」，字走主题文件 |
| 换工具时风格漂移 | 锁图标换了一个生图接口，另写了一段英文描述，没拼项目的风格前缀；碰巧接近，但下一张就未必 | 所有工具都从同一个 `style` 拼提示词，并记录实际提示词 |
| 生成失败时的退路 | 生图接口连续三次网络错误，只能保留旧图和缺图回退；用户随后定规则 | 如实报告失败次数和错误；占位必须写进待办，不当成完成 |
