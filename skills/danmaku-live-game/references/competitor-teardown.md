# 竞品拆解

第一天就做，在写任何代码之前。修仙案例的第一版就是因为没有逐帧对照竞品录像、先按自己的理解做，整体方向偏了，只能推倒重来。

## 素材

- 直播录像（最好 3 段以上，覆盖不同事件）、观众端小程序 / 面板录像、截图。
- 网上通常查不到这类直播玩法的数值表（搜到的多是同名手游），所以数值只能从录像里读，读不到的自己定，并标清楚。
- 先判断竞品属于哪一类（`genre-patterns.md`），拆的时候就知道重点看什么：席位养成看席位信息和事件轮换，阵营对抗看礼物怎么改变战局，竞速看一局多长、怎么避开押注。

## 录像怎么看

- 每秒抽一帧拼成联系表：`ffmpeg -i 录像.mp4 -vf "fps=1,scale=360:-1,tile=10x6" sheet_%03d.png`，一张图看一分钟，事件切换一眼就能找到。
- 用一张计时表逐段记：时间戳、事件名、倒计时读数、画面上的指令提示。同一事件至少看两次出场，取典型值。
- 记下观众的真实弹幕：哪些指令最常见、有哪些写错的写法（以后都是别名）。
- 记下礼物从出现在弹幕区到游戏里出效果的间隔，以及大礼物效果占多大画面、持续几秒。
- 记下人少和人多时的差别：怪的数量、BOSS 血量、满座以后新观众怎么办。

## 拆成五张表，写进 `docs/DESIGN.md`

### 1. 画面结构

| 位置 | 竞品内容 | 本项目 |
|---|---|---|
| 顶部 | Logo、轮播活动横幅、事件栏（左说明 · 中地图/宗门名牌 · 右事件名 + 倒计时 + 指令提示） | |
| 左侧 | 竖排入口图标（宗门、副本、活动、公告…） | |
| 席位 | 编号浮空石台；头像圆框、竖排境界牌、属性数值、称号牌、宠物、翅膀/光环 | |
| 直播间互动面板 | 玩法助手 + 礼物效果列表 | 平台侧配置，不进游戏画面 |
| 观众端面板 | 背包、幻化、灵宠、排行… | 不在直播画面弹出；以后做手机端 |

关键判断：**竞品小程序里的背包、幻化界面就是游戏本体的养成面板**，上面列出的玩法都在范围内，不是另一个产品。

### 2. 弹幕指令

| 指令 | 来源【参考/设计】 | 作用 | 状态 |
|---|---|---|---|
| 加入 / 加入N | 参考 | 入座，N 指定席位 | |
| 击退 | 参考 | 自动攻击 | |
| a编号 | 参考 | 指定攻击某只怪 | |
| 突破 / 签到 / 摸索 / 修炼 … | | | |

数字指令按当前事件解释，记下竞品在每个事件里数字是什么意思。

### 3. 事件轮换与时长

逐段录像计时：每个事件多长、等待多长、结算多长、一轮多长、一轮里哪个事件出现几次。**这张表直接决定直播节奏**，不要为了调试方便用短时长代替（调试时长另配）。

| 事件 | 时长 | 玩法 | 来源 |
|---|---|---|---|
| 妖兽入侵 | 几分钟 | 怪带字母编号和血条游走，自动/指定攻击 | 参考 |
| … | | | |

### 4. 礼物映射

| 平台礼物 | 价格 | 竞品效果 | 本项目效果【设计】 |
|---|---|---|---|

礼物名是平台的，必须照用；效果描述要按本项目主题写。礼物入口不进游戏画面，由主播叠加，游戏只接收礼物事件、播放效果。

### 5. 数值

每一项都标【参考】（录像里读到的）或【设计】（我们定的，可调，写在 `config/`）。至少包括：等级曲线、属性曲线、奖励公式、掉率、价格、事件参数。

## 对齐什么、不对齐什么

- **对齐**：美术风格（例如 Q 版大头）、画面密度与节奏、打怪方式、大数字和大特效、事件循环结构。
- **不照搬**：图片、名字、界面素材都用自己的；押资源这类不友好的设计可以改（这个项目把所有「押」类玩法改成了免费）。
- **合理为主**：不必在每一项上都超过竞品，先把核心循环做扎实，再迭代。

## 用来判断有没有对齐的问题

- 截一张自己的画面和竞品截图并排看：密度、字号、数字大小、特效面积是否同一个量级？
- 竞品一轮多长、主事件占多少？自己的呢？
- 观众只发「加入」「击退」两条，能不能玩完整一轮？
