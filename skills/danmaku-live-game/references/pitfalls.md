# 踩过的坑

每一条都来自真实的抖音弹幕游戏开发：未标注的来自一个弹幕修仙项目（对标抖音头部弹幕修仙玩法），标「上班案例」的来自一个上班社畜主题的原创弹幕玩法；「模拟数据混入」「生图密钥」两条是开工时就定下的规则。美术和截图验收的坑集中在 `art-pipeline.md` 末尾，这里不重复。

| 坑 | 发生了什么 | 怎么避免 |
|---|---|---|
| 没先拆竞品 | 第一版按自己的理解做，整体方向偏了，推倒重来 | 第一天拆竞品录像，写成表（`competitor-teardown.md`） |
| 当成单机游戏 | 做了背包 / 幻化大面板卡片，用户指出直播画面是大家共享的，整套删掉 | 每个功能先问画面是给谁看的；个人信息只在席位上方飘两行 |
| 主题层做晚了 | 中文名字散在 20 多个规则和画面文件里，抽离花了一整步 | 第一天建 `Words` 和主题文件，规则代码里不写给人看的字 |
| 调试时长当正式时长 | 一轮 15 分钟、打怪每场 20 秒，用户对比竞品后要求拉长 | 时长从竞品录像来；调试时长单独配置 |
| 只改时长不改奖励 | 打怪拉长后升级快了 2.6 倍 | 改时长后跑一小时实测，同步调奖励比例 |
| 实测脚本不像玩家 | soak 不发「突破」，人人卡在第九层，两种配置都是「升 8.0 层」 | 模拟关键操作；数据太整齐要怀疑 |
| 测试写死时长 | 调时长后 20 项测试失败 | 用 `finish_event` 等按配置的辅助函数 |
| 窗口被遮挡 | macOS 停止绘制，帧时间出现 40–144 ms 尖峰，查了很久；截图卡住或连拍同一帧 | 截图 / 测性能时窗口置顶，检测并打印遮挡，数据作废 |
| 引擎自带录制 | Godot 录 1080p AVI 每帧近 3 MB，差点写满磁盘 | ffmpeg 录屏 + 裁剪 + 压缩 |
| 类名冲突 | 想叫 `Theme`，和 Godot 自带的 Theme 资源重名 | 叫 `Words` |
| 新类找不到 | 加了 `class_name` 后无头脚本报未声明，脚本挂住不退出 | 先 `--import --quit`；无头命令加 `perl -e 'alarm N; exec @ARGV'` 超时 |
| 从文案里截字 | 面板备注用 `get_slice("，", 0).replace("兑换需", "")` 从中文消息里截出价格，一换主题就坏 | 写返回结构化结果的函数 |
| 重构打乱随机数（预防） | 主题抽离时要改模拟观众的抽签代码；数组长度或顺序一变，后面所有随机结果都错开，截图和快照都没法比 | 保持数组长度和顺序 |
| 首次显示卡顿 | 第一次用到某个图标时读盘，帧时间 40–70 ms | 启动时预载全部贴图 |
| 押资源 | 竞品的幻阵、夺宝要押灵石；用户判断观众亏光就会走，全部改成免费 | 免费参与，赢了奖更多，输了有安慰奖 |
| 刷屏挡棋盘 | 同一观众连续查询，提示一直挡住棋盘 | 同一人大提示限频，新的替换旧的 |
| 模拟数据混入（规则） | 模拟观众的数据如果被当成真实观众数据，结论就是假的 | uid 前缀 `sim:` / `local:`，报告里写明「模拟观众」 |
| 生图密钥（规则） | 密钥写进文件或从别的项目里找，都有泄露风险 | 只从环境变量读，没有就问用户 |
| 截图时时钟照走（上班案例） | 窗口被遮挡的几十秒里游戏继续跑，那几个阶段的截图整段错过 | 截图导演在窗口不画 / 图片和上一张一样时冻结游戏时钟，超时放弃并按名字列出缺图 |
| 类型化数组参数（上班案例） | `Array[String]` 参数收到字面量数组运行时才报错，`--check-only` 查不出 | 参数用 `Array`，或先声明带类型的变量再传 |
| 录屏没有权限（上班案例） | ffmpeg 的屏幕设备在没有「屏幕录制」权限时直接消失 | 录像脚本让用户在自己有权限的终端里跑；AI 不改系统设置 |
| lambda 按值捕获（上班案例） | 测试里 `clock = func(): return day`，之后改 `day` 不生效 | 用数组或字典包一层 |
| 名字跨系统撞车（上班案例） | 送礼等级叫「合伙人」「董事长」，职级里也有，观众分不清是摸鱼升上去的还是送礼送的，整套改名为「甲方」 | 新系统起名前把主题文件里所有名字表过一遍；`check_theme.py` 会对跨表重名给警告 |
| 一个数干三件事（上班案例） | 摸鱼值同时是经验、排名分数和工钱来源，桌上的累计数只涨不花，观众问「摸鱼值能干嘛」 | 经验、钱、分数分成三个数，画面上各显示各的（`casual-game-design` 核心原则 10） |
| 时间心算漏项（上班案例） | 一轮加几个活动时漏算每个活动前后 15 秒等待 + 10 秒结算，写成「摸鱼少 2.5%」，实际少 17.9% | 排期改动用 `loop_length.py` 算，不心算 |
| 对照参数没传（上班案例） | 模拟脚本里标「1 口锅」的对照没显式传参数，跑的其实是默认 2 口锅，那几行结论作废 | 对照组的参数显式传，输出里打印实际参数 |
| 近似模型当证据（上班案例） | 节奏模拟不含前两级折扣，报「首次升职太慢」；引擎实测其实达标，差点照着报警加奖励 | 先列出模拟和真实规则的口径差异，再决定信哪个 |
| 满座进不来（上班案例） | 30 个座被早就走了的人占着，新观众发「上班」被拒，新来的送礼观众个人效果全白送 | 闲置超过 10 分钟的座可被新人换掉；送礼多的人免换（只做展示特权） |
| 原图进游戏（上班案例） | 1254px、约 1 MB 的锁图标直接画成 28px、一次 7 个；同一轮截图运行出现 50–120 ms 的卡顿，它是头号嫌疑 | 所有图走清单 + 缩放，`check_art.py` 检查（`art-pipeline.md`） |
