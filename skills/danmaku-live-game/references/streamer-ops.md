# 主播与一场直播

弹幕游戏是主播开播用的工具。主播是第一个用户：要能一个人开播、看得懂发生了什么、找得到话说。游戏再好玩，主播接不住，直播间就冷了。

## 开播前

- 游戏窗口固定竖屏 1080×1920，用直播伴侣或 OBS 捕获窗口推流。窗口不要被遮挡、不要最小化（macOS 下窗口被遮挡时会停止绘制，推出去的画面会卡住）。
- 礼物说明、玩法说明这类入口由主播叠加在游戏画面外面，游戏画面里不做礼物入口。
- 主播控制台单独一个窗口（不进推流画面），放在另一块屏幕上。
- 提供一份一页纸的主播说明：怎么启动、怎么建宗 / 改名、出问题怎么重连、各礼物触发什么。

## 主播控制台要有的功能

| 功能 | 为什么 |
|---|---|
| 连接状态（推送是否在收、最近一条消息几秒前） | 主播第一时间知道是不是断了 |
| 建宗 / 改名（直播间的名字） | 归属感从名字开始 |
| 跳到下一阶段、暂停 | 主播要说话或处理意外时 |
| 发福利（全场小加成，限次数） | 主播拉气氛的工具 |
| 只在游戏内屏蔽某个 uid | 处理捣乱的人，不依赖平台操作 |
| 低配开关 | 主播电脑差时保推流 |
| 「现在可以说什么」提示 | 见下面「口播点」 |

## 一场直播的结构

| 阶段 | 时长 | 要做到 |
|---|---|---|
| 开场 | 前 5–10 分钟 | 人少也能玩：前几个入座的人立刻有奖励；空席位写「发 加入 入座」而不是空白 |
| 中段 | 大部分时间 | 事件轮换，每 15–30 分钟一个高光（BOSS 倒下、稀有掉落），主播有东西可讲 |
| 收尾 | 最后几分钟 | 今日榜结算、预告明天（BOSS 剩多少血、限时外观还剩几天） |

## 人少和人多

- **人少（3–10 人）**：怪的数量、BOSS 血量按在座人数和输出缩放，并设下限；不用模拟观众冒充真人填满画面。系统角色可以有，但要看得出是系统的。
- **人多（30 席坐满以后）**：闲置久的位置让给新来的人；没座位的人点赞、送礼也有效果；弹幕洪峰按 `platform-integration.md` 处理。

## 口播点：给主播制造能说的话

主播最怕没话说。游戏要主动制造「现在值得说一句」的时刻，并用一句话写在事件栏或播报里，让主播照着念也行：

- 倒计时最后 10 秒：「还有 10 秒，没加入的赶紧」。
- BOSS 只剩 5% 血：「最后一击有额外奖励」。
- 突破成功或失败、榜首易主、有人拿到稀有外观。
- 大礼物署名播报：主播点名感谢。

这些时刻同时在主播控制台上提示一行，主播不用盯着整个画面找。

## 每场直播的数据复盘

每场直播写一份日志（真实数据，和模拟数据分开存）。下播后看：

| 指标 | 用来判断 |
|---|---|
| 入座人数峰值、平均入座时长 | 留不留得住 |
| 发过有效指令的人数 / 入座人数 | 指令是不是太难 |
| **未识别弹幕前 20 名** | 观众实际怎么写；高频的写法补成别名，这是最便宜的改进 |
| 每种指令的使用次数 | 哪些指令没人用，可以删或合并 |
| 每个事件的参与率 | 哪个事件冷场 |
| 各档礼物次数 | 价位梯度是不是合理 |
| 断线次数、最长断线 | 接入稳不稳 |

再问主播两个问题：哪一刻最好说话？哪一刻冷场？答案比数据更早暴露问题。

真实数据只用于这个直播间的复盘，昵称和头像不外传；结论写进 `docs/NEXT.md` 时只写统计数字。
